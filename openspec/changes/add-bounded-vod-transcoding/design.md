## Context

HEVC/AC3/EAC3 en MKV no garantiza soporte en Chrome. MediaError 4 y 206 no identifican individualmente el códec causante, pero justifican transformar ambos flujos a un perfil web conocido. El proveedor permite una conexión por cuenta. El transporte Go ya valida procedencia, DNS/IP pública, TLS y redirects. FFmpeg no debe acceder directamente a URLs del proveedor ni interpretar manifiestos/URLs arbitrarios.

## Goals / Non-Goals

Reproducir archivos VOD incompatibles a través de una conversión local controlada, preservando privacidad, sesión y búsqueda temporal. Priorizar reproducción directa cuando funciona. No prometer 4K ni tiempo real en cualquier CPU, no omitir controles SSRF, no saltarse límites ni introducir una segunda descarga para sondeo. No convertir directo ni HLS en esta primera fase: solo archivos VOD gestionados por el gateway.

## Decisions

1. **Activación y contrato.** `VOD_TRANSCODING_ENABLED=false` por defecto; en local se configura true una vez construida la imagen con FFmpeg. Endpoint POST de conversión sobre playback existente, con cookie/CSRF/propiedad y posición inicial acotada. Solo movie/episode de formato file; no recibe URLs ni argumentos. Web intenta automáticamente una sola vez por intento tras MediaError 3/4 o diagnóstico equivalente de formato/decodificación, únicamente cuando no hay un fallo de transporte confirmado. Muestra «Preparando versión compatible · hasta 720p» y conserva opción de volver. Errores de auth, 409, timeout/red o estado upstream no disparan conversión ciega. Si el diagnóstico tarda o la causa es desconocida, ofrecer acción explícita «Probar versión compatible» sin bucles automáticos. Servicio deshabilitado/saturado devuelve código accionable y mantiene el catálogo accesible.
2. **Una conexión por cuenta.** Reutilizar el lease existente y su identidad de proveedor. Antes de iniciar FFmpeg, navegador pausa, retira src, destruye HLS y libera requests; API bloquea nueva lectura directa de ese playback, cancela sus requests upstream y espera cierre efectivo. Después arranca el gateway. No crear otro lease ni otro playback. Una conversión mantiene la cuenta ocupada. No usar ffprobe en paralelo. Si la cancelación no concluye, falla la transición en vez de abrir otra conexión. Seek/retry detiene y espera el trabajo anterior antes de abrir el nuevo; una conexión por cuenta también durante sondas/rangos internos. El gateway admite una única request upstream activa, cancela la previa y espera cierre o rechaza la adicional, sin cola sin límite. Otros usuarios con la misma cuenta siguen recibiendo PLAYBACK_LIMIT.
3. **Entrada sin credenciales en proceso.** API crea listener efímero HTTP exclusivo en loopback, ruta fija `/input`, unido en memoria a un único trabajo y su fuente. El comando contiene únicamente `http://127.0.0.1:puerto/input`, nunca credenciales, URL upstream ni token reutilizable. No publicar ese puerto en Compose. El listener vive en el contenedor API sin procesos de usuarios no confiables; no es un endpoint público ni usa parámetro URL. El gateway Go aplica GET/HEAD/Range a la fuente vinculada usando su transporte validado, revalida nuevos destinos y no refleja Location ni cabeceras privadas a FFmpeg. Cierra listener al cancelar; no deja autorización permanente. Evitar seguir enlaces embebidos: limitar FFmpeg a demuxers de archivos expresamente admitidos y protocolos `http,tcp`, sin HLS, concat, file como entrada, dispositivos, ejecuciones o URLs de metadatos. Validar Range/longitudes y no almacenar archivo original. Un paquete multimedia malformado sigue siendo riesgo de parser: imagen parcheada, usuario sin privilegios y límites de proceso.
4. **Conversión reproducible.** Construir args con `exec.CommandContext`, nunca shell. Perfil fijo: primera pista de vídeo/audio opcionales; sin subtítulos ni datos; vídeo libx264 preset ultrafast, yuv420p, dimensión máxima 1280x720 manteniendo relación/paridad y sin upscale, CRF aproximado 23 con techo de 2,5 Mb/s y buffer acotado, audio AAC estéreo 128 kb/s, hilos codec/filtro máximos 2/1, keyframes forzados cada 4 s. HLS TS de segmentos de 4 s, lista rodante de hasta 12 y limpieza de segmentos antiguos; no anunciar ENDLIST hasta acabar. Entrada `-ss` antes de `-i` para seek eficiente cuando origen admite rangos; usar `-re` para acompasar lectura a tiempo real y evitar que el encoder adelante la ventana rodante al consumidor; arranque y progreso siguen sujetos a timeout. Si una versión comprobada permite burst inicial, solo habilitarlo con prueba de que no adelanta más de dos segmentos. El muxer solo escribe en directorio privado de trabajo con nombres generados por servidor; no aceptar paths/args del usuario. La implementación fija exactamente el comando y lo prueba con fixtures, incluida ausencia de audio y orientación/aspecto.
5. **HLS privado.** El API sirve manifiesto/segmentos por IDs opacos bajo autorización de usuario/playback/generación; no expone nombres de disco, URLs internas ni proveedor. Reescribe referencias a rutas autorizadas, limita manifiesto y tamaño de segmento; rechaza traversal y extensiones/IDs ajenos. Cache-Control no-store. No servir .tmp, archivos parciales ni lista antes del primer segmento completo; publicar atómicamente. Generaciones revocadas devuelven expiración y no abren proveedor. Heartbeat conserva lease y la cancelación detiene toda la cadena. HLS.js y HLS nativo consumen el mismo formato.
6. **Seek y progreso honestos.** Conversión progresiva no ofrece Range/206 sobre MP4 ficticio ni acceso a partes aún no convertidas. Mantener offset lógico separado del tiempo local del manifiesto y guardar `offset + video.currentTime`. Usar duración total solo de metadata fiable obtenida en el mismo flujo/metadata ya existente, nunca inventarla. Mostrar timeline propio para conversión cuando hay duración conocida: POST seek con offset finito >=0 y menor que duración, máximo uno en curso, debounce y generaciones monotónicas. Detener trabajo y upstream previos; reiniciar FFmpeg con -ss, nueva generación y reiniciar tiempo local. El navegador nativo solo puede buscar dentro de su ventana disponible; no presentar esa ventana como duración completa. Sin duración fiable, indicar «Duración desconocida» y permitir solo seek a posiciones validadas ya conocidas, sin slider completo. Guardar avance lógico también con duración desconocida usando `durationSeconds=0`, ya admitido por contrato/tabla existentes; no guardar duración de la ventana como duración del título. Volver al catálogo guarda offset+tiempo local antes de cancelar, preserva filtros y reabrir recupera esa posición. Si la reproducción directa vuelve a fallar, el fallback empieza desde la posición guardada, sin sumarla dos veces. La precisión depende de keyframes/rangos; registrar offset real cuando esté disponible. Si el upstream no admite seek eficiente, no descargar desde cero sin límite: error explícito de búsqueda no disponible, conservando posibilidad de reiniciar desde principio.
7. **Recursos y ciclo de vida.** Inicialmente 1 trabajo global, sin cola; un POST duplicado idempotente devuelve trabajo actual. Tiempo de preparación máximo 60 s, sin progreso de salida por 30 s causa fallo saneado, vida máxima 6 h e inactividad de consumidor 60 s cancela (pausa larga requiere volver a preparar al reanudar). Un trabajo no puede escribir más de 256 MiB; comprobar presupuesto independientemente de cantidad de segmentos. Salida efímera en tmpfs o volumen efímero acotado: 256 MiB si tmpfs, contabilizado dentro del límite de memoria. Compose API: cpus 2.0, mem_limit 1536m y pids_limit 128, documentando que son límites del servicio completo y Go necesita margen; no confiar solo en hilos de encoder. Diferenciar fallo de capacidad/proceso de fallo upstream. Cancelar grupo de procesos y esperar Wait; matar tras gracia máxima 3 s, cerrar pipes/listener, borrar directorio. Limpieza al salir, logout, expiración lease, eliminación fuente, límite, reinicio/shutdown y error. No persistir trabajo en BD ni recuperar medios tras reinicio. Actividad heartbeat sola no mantiene un transcode abandonado si no consume manifiestos/segmentos.
8. **Logs/telemetría.** No enviar stderr/stdout de FFmpeg a logs; puede incluir datos de entrada. Consumir progreso por pipe con claves numéricas permitidas; descartar texto libre y mantener solamente salida numérica, categoría y exit code saneados. Entorno hijo mínimo sin secretos API/DB/IPTV y stdin cerrado. Ningún error retornado contiene argv, hostname, URL, paths o stderr. No poner credenciales en archivos temporales. Pruebas inspeccionan argv/env/logs de hijo y API con secretos centinela.
9. **Disponibilidad y CPU.** Un 4K HEVC en software puede no mantener tiempo real con 2 CPU incluso a 720p. Mostrar progreso inicial; si no produce primer segmento antes de 60 s o se detiene durante 30 s, cancelar y recomendar versión compatible/1080 del catálogo. No aumentar recursos automáticamente ni cambiar a GPU sin preparar despliegue/driver. El muestreo exitoso de un título no garantiza toda la película; verificar sostenimiento durante muestra y documentar hardware/duración. No afirmar velocidad de conversión basándose solo en proceso vivo.

## Risks / Trade-offs

FFmpeg amplía superficie de parser y tamaño de imagen. Software 4K→720p consume CPU y reduce calidad; activar requiere recursos disponibles. El gateway protege credenciales y SSRF pero añade complejidad al seek/rangos; un puerto loopback no protege contra código arbitrario ya ejecutándose dentro del mismo contenedor. Por eso no compartir contenedor con extensiones o procesos de usuarios. HLS rodante requiere timeline lógico y revocación por generación. Con un solo trabajo, otros usuarios podrían necesitar reproducción directa o esperar manualmente; no crear cola ni incrementar conexiones para ocultarlo.

## Migration Plan

Actualizar `docker/api.Dockerfile` para instalar FFmpeg desde repositorio de la imagen base y comprobar en build/distribución soporte libx264/AAC; no asumir binarios del host. Ejecutar usuario walactv existente; directorio efímero con propietario correcto y modo privado. API lee `VOD_TRANSCODING_ENABLED` (default false), Compose pasa el nombre/valor no secreto y aplica presupuestos anteriores. `.env.example` documenta nombre y false, `.env` local puede activar true sin tocar otros secretos. No publicar puertos de gateway ni montar host Docker/GPU; no añadir servicios ni volúmenes persistentes. PostgreSQL no cambia y migrador/bootstrap idempotentes mantienen orden; `API_REPLICAS=1`. No modificar otras aplicaciones. Reinicio/rollback cancela trabajos, elimina efímeros y conserva BD; imagen anterior no entiende fallback, por lo que nuevas llamadas deben manejar deshabilitado/404 con error claro. No hay despliegue de producción autorizado. Documentar política de pausa/seek y recursos.

## Validation

Fixtures generados localmente: MKV HEVC/EAC3 o AC3 y MP4 H.264/AAC, vídeo sin audio, aspecto vertical y rangos. Verificar arranque HLS, MIME/referencias privadas, decodificación/avance en navegador, offset/seek/generación/progreso lógico, sin usuario ajeno; una conexión upstream máxima incluso durante transición/seek/metadata/cancelación. Probar deshabilitado/saturación, timeout inicial, bloqueo de salida, disco/memoria acotados, salida malformada y kill/limpieza, SSRF desde entrada/manifiesto malicioso, ausencia de secretos en argv/env/logs/respuestas, base/control inalterados. Tests no usan proveedor real; coordina principal muestras reales secuenciales al menos de MKV 4K incompatible y otro VOD, registrando CPU/duración/avance/seek y límites. Go relevante con race, build web, validación OpenSpec, Compose sin imprimir secretos, versión/capacidades FFmpeg de imagen y salud API bajo conversión.
